# سامانه نوبت‌دهی آنلاین — پروژه Django

این پوشه، پیاده‌سازی اولیه بخش بک‌اند فاز اول پروژه است. تمرکز آن روی مدل‌های دیتابیس، قوانین اصلی سامانه و عملیات حساس نوبت‌دهی است؛ رابط کاربری عمومی (صفحات HTML/CSS)، ثبت‌نام و ورود سفارشی و API در فازهای بعدی اضافه می‌شوند.

## فناوری‌ها

- Python 3.13 یا 3.14
- Django 6.1.2
- SQLite برای توسعه و ارائه دانشگاهی
- Django Admin برای مدیریت اولیه کاربران، متخصصان، زمان‌ها، نوبت‌ها و بازخوردها

## اجرای پروژه در ویندوز (PowerShell)

```powershell
# 1) وارد پوشه پروژه شوید
cd appointment_booking_django

# 2) ساخت محیط مجازی
py -3.14 -m venv .venv

# 3) فعال‌سازی محیط مجازی
.venv\Scripts\Activate.ps1

# 4) نصب وابستگی‌ها
python -m pip install -r requirements.txt

# 5) ساخت فایل‌های migration اولیه
python manage.py makemigrations appointments

# 6) ایجاد جداول دیتابیس
python manage.py migrate

# 7) ساخت مدیر سامانه
python manage.py createsuperuser

# 8) اجرای سرور توسعه
python manage.py runserver
```

اگر Python 3.14 نصب نیست، در دستور ساخت محیط مجازی به‌جای `py -3.14` از نسخه نصب‌شده خود (مثلاً `py -3.13`) استفاده کنید.

سپس پنل مدیریت در نشانی `http://127.0.0.1:8000/admin/` در دسترس است.

## مدل‌های پیاده‌سازی‌شده

1. `User`: حساب کاربری با نقش کاربر عادی یا متخصص. مدیر سامانه با قابلیت‌های `is_staff` و `is_superuser` جنگو مدیریت می‌شود.
2. `SpecialistProfile`: اطلاعات تخصصی متخصص و وضعیت بررسی مدیر (`pending`، `approved`، `rejected`).
3. `AvailabilitySlot`: بازه زمانی قابل ارائه توسط متخصص.
4. `Appointment`: درخواست نوبت و وضعیت آن.
5. `Review`: امتیاز و نظر مربوط به نوبت انجام‌شده.

## قوانین مهم پیاده‌سازی

- هر متخصص باید پیش از تعریف زمان‌های قابل رزرو توسط مدیر تأیید شود.
- بازه‌های فعال یک متخصص نباید با یکدیگر هم‌پوشانی داشته باشند.
- فقط کاربران عادی می‌توانند درخواست نوبت ثبت کنند.
- برای هر بازه زمانی فقط یک نوبت فعال در وضعیت `pending` یا `confirmed` مجاز است. محدودیت یکتایی شرطی در دیتابیس نیز این قانون را پشتیبانی می‌کند.
- نوبت ردشده یا لغوشده، بازه را آزاد می‌کند و سابقه آن حذف نمی‌شود.
- تغییر زمان، نوبت را به وضعیت `pending` برمی‌گرداند تا متخصص زمان جدید را دوباره بررسی کند.
- فقط نوبت `completed` واجد شرایط ثبت بازخورد است و هر نوبت حداکثر یک بازخورد دارد.

## عملیات اصلی

منطق عملیات اصلی در `appointments/services.py` متمرکز شده است:

- `request_appointment`: ثبت درخواست با بررسی مجدد آزاد بودن زمان و محافظت در برابر رزرو تکراری.
- `decide_appointment`: تأیید یا رد درخواست توسط متخصص مالک بازه.
- `cancel_appointment`: لغو نوبت توسط کاربر ثبت‌کننده.
- `reschedule_appointment`: تغییر زمان نوبت و بازگشت آن به حالت انتظار تأیید.
- `mark_appointment_result`: ثبت انجام‌شدن جلسه یا عدم حضور کاربر توسط متخصص.
- `submit_review`: ثبت بازخورد برای نوبت انجام‌شده.

## اجرای تست‌ها

پس از نصب وابستگی‌ها و اجرای migrationها:

```powershell
python manage.py test appointments
```

## نکات توسعه و امنیت

- `SECRET_KEY` فعلی فقط برای محیط توسعه است؛ پیش از انتشار باید با متغیر محیطی جایگزین شود.
- در محیط واقعی باید `DEBUG=False`، دامنه‌های مجاز، HTTPS، سیاست پشتیبان‌گیری و پایگاه داده مناسب پیکربندی شوند.
- `select_for_update()` برای محافظت از عملیات هم‌زمان در پایگاه داده‌هایی مانند PostgreSQL مفید است؛ محدودیت یکتایی شرطی دیتابیس نیز آخرین لایه جلوگیری از رزرو فعال تکراری است.
- در نسخه فعلی، مدیر از طریق Django Admin پروفایل متخصص را بررسی می‌کند؛ فرآیند اختصاصی و رابط کاربری آن در فاز بعدی ساخته خواهد شد.
